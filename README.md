# Sakila Movie Search

Учебное приложение для поиска фильмов в демонстрационной базе данных MySQL
`sakila`. Проект предоставляет два интерфейса к общей бизнес-логике:

- консольное приложение;
- веб-приложение на FastAPI и Jinja2.

Поисковые данные берутся из MySQL, а история запросов сохраняется в MongoDB.
Пользователь может просматривать последние и наиболее популярные запросы.

## Цель проекта

Цель проекта — показать практическое применение Python для работы сразу с
двумя типами баз данных и несколькими пользовательскими интерфейсами.

В проекте реализованы:

- разделение приложения на модули;
- параметризованные SQL-запросы;
- повторное использование общей логики консолью и веб-интерфейсом;
- работа с MySQL и MongoDB;
- постраничный вывод результатов;
- кеширование просмотренных страниц;
- обработка и журналирование ошибок;
- автоматические тесты веб-маршрутов.

## Возможности

- поиск фильмов по полному названию или его части;
- поиск по жанру и диапазону годов выпуска;
- проверка пользовательского ввода;
- вывод результатов страницами по 10 фильмов;
- переход между страницами результатов;
- кеширование просмотренных страниц в консольной версии;
- сохранение истории поиска в основную MongoDB и MongoDB Atlas;
- вывод пяти самых популярных запросов;
- вывод пяти последних уникальных запросов;
- консольный интерфейс с цветным форматированием;
- веб-интерфейс с адаптивными HTML-шаблонами;
- понятные сообщения при ошибках MySQL, MongoDB и HTTP-запросов;
- раздельное журналирование событий разных уровней.

### Направление зависимостей

```text
Консоль: main.py → ui → database → MySQL / MongoDB

Веб:     app.py  → database → MySQL / MongoDB
                    ↓
                 templates
```

Оба интерфейса используют общий слой `database`. SQL-запросы не выполняются
непосредственно в консольном или веб-интерфейсе.

## Как выполняется поиск

```text
1. Пользователь вводит название либо выбирает жанр и годы.
2. Интерфейс проверяет входные данные.
3. film_service.py запрашивает количество найденных фильмов.
4. executor.py выполняет параметризованный SQL-запрос к MySQL.
5. Интерфейс получает одну страницу результатов.
6. Параметры поиска и количество результатов сохраняются в MongoDB.
7. Пользователь просматривает результаты и переходит между страницами.
```

История сохраняется только при открытии первой страницы, поэтому переходы по
пагинации не увеличивают статистику популярности одного и того же поиска.

## Работа с MySQL

База MySQL `sakila` является основным источником данных о фильмах.

- `queries.py` хранит тексты SQL-запросов;
- `connection.py` создаёт соединение;
- `executor.py` выполняет запрос и возвращает строки с заголовками;
- `film_service.py` предоставляет интерфейсам понятные операции, например
  `count_films_by_name()` и `get_films_by_genre()`.

Пользовательские значения передаются в SQL отдельно от текста запроса. Это
уменьшает риск SQL-инъекций.

## Работа с MongoDB

MongoDB хранит историю поиска в виде документов:

```python
{
    "search_type": "by_name",
    "query": {"keyword": "academy"},
    "results_count": 12,
    "created_at": datetime(...),
}
```

При запуске приложения создаются долгоживущие объекты `MongoClient`, которые
повторно используют пулы соединений. При завершении приложения клиенты
закрываются:

- консольная версия управляет ими через `try/finally` в `main.py`;
- веб-версия использует механизм `lifespan` FastAPI.

Поисковая история записывается в основную MongoDB и MongoDB Atlas. Ошибка
сохранения истории не должна прерывать основной поиск фильмов.

## Веб-маршруты

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/` | форма поиска |
| `GET` | `/search` | поиск и постраничный вывод результатов |
| `GET` | `/popular` | пять популярных запросов |
| `GET` | `/recent` | пять последних уникальных запросов |
| `GET` | `/docs` | автоматически созданная документация FastAPI |

Jinja2 получает данные из Python и формирует итоговые HTML-страницы. Общий
шаблон `base.html` содержит навигацию, стили и нижнюю часть страницы.

## Установка

Клонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone <repository-url>
cd PROJECT_KUZAN
```

Создайте виртуальное окружение.

```powershell
python -m venv .venv
```

```bash
python3 -m venv .venv
```

Установите зависимости:

```bash
python -m pip install mysql-connector-python pymongo colorama colorlog tabulate fastapi uvicorn jinja2 pytest httpx
```

## Конфигурация

Создайте файл `config/local_settings.py`:

```python
dbconfig = {
    "host": "localhost",
    "port": 3306,
    "user": "your_mysql_user",
    "password": "your_mysql_password",
    "database": "sakila",
}

MONGODB_URL_WRITE = "mongodb://localhost:27017"
MONGODB_URL_READ = MONGODB_URL_WRITE
MONGODB_URL_ATLAS = "mongodb+srv://user:password@cluster.example.net/"
```

Названия MongoDB-базы и коллекции задаются константами `DB_NAME` и
`COLLECTION_NAME` в `database/mongo_history_write.py`.

> Не публикуйте реальные пароли и строки подключения. Каталоги `config/` и
> `logs/` исключены из Git.

## Запуск консольной версии

```bash
python main.py
```

После запуска пользователь получает меню поиска и просмотра истории. Команда
`q` завершает программу и закрывает MongoDB-клиенты.

## Запуск веб-версии

```bash
python -m uvicorn app:app --reload
```

После запуска откройте:

```text
http://127.0.0.1:8000
```

Параметр `--reload` подходит для разработки: сервер автоматически
перезапускается после изменения исходного кода.

## Тестирование

Основные веб-тесты:

```bash
python -m pytest tests/test_web.py -v
```

Тесты используют `TestClient` FastAPI и подменяют обращения к внешним базам,
поэтому проверяют маршрутизацию, валидацию, пагинацию, формирование истории и
рендеринг страниц независимо от доступности MySQL и MongoDB.

Проверяемые сценарии включают:

- вывод жанров и диапазона годов;
- поиск по названию;
- поиск по жанру и годам;
- ограничение годов диапазоном базы;
- отклонение неправильного ввода;
- правильный `OFFSET` при пагинации;
- отображение популярных и последних запросов;
- открытие и закрытие MongoDB в жизненном цикле веб-приложения.

`test_connection.py` и `test_mongo.py` содержат диагностические проверки.
Некоторые из них требуют реальных подключений и могут изменять тестовые данные.

## Обработка ошибок

- ошибки недоступности внешнего сервиса преобразуются в
  `ServiceUnavailableError`;
- ошибки MySQL и MongoDB журналируются;
- консоль показывает понятное текстовое сообщение;
- веб-версия формирует HTML-страницу с соответствующим HTTP-статусом;
- ошибка сохранения истории не отменяет уже выполненный поиск фильма;
- закрытие MongoDB выполняется в `finally`, поэтому ресурсы освобождаются и
  после ошибки.

## Журналирование

Консольная версия создаёт журналы:

```text
logs/
├── debug.log
├── info.log
└── errors.log
```

Журналы помогают отделить пользовательское сообщение от технических сведений,
необходимых разработчику для диагностики.

## Ключевые решения проекта

1. **Разделение ответственности.** Интерфейсы отвечают за ввод и вывод, а
   слой `database` — за работу с данными.
2. **Параметризованные SQL-запросы.** Значения пользователя не объединяются с
   SQL простой конкатенацией строк.
3. **Один MongoClient на адрес.** Пул соединений повторно используется в
   течение работы приложения.
4. **Гарантированное освобождение ресурсов.** Клиенты закрываются через
   `finally` или FastAPI `lifespan`.
5. **Независимость основного поиска от истории.** Недоступность MongoDB при
   записи не должна блокировать поиск в MySQL.
6. **Пагинация.** Приложение не загружает все найденные фильмы за один раз.
7. **Кеш консольных страниц.** Повторное открытие просмотренной страницы не
   требует повторного SQL-запроса.

## Сценарий презентации проекта

### 1. Постановка задачи

> Цель проекта — создать приложение для поиска фильмов в MySQL `sakila` с
> консольным и веб-интерфейсом, а также сохранять статистику поиска в MongoDB.

### 2. Демонстрация возможностей

1. Выполнить поиск фильма по части названия.
2. Показать количество результатов и переход на следующую страницу.
3. Выполнить поиск по жанру и диапазону годов.
4. Открыть страницы популярных и последних запросов.
5. При необходимости показать аналогичные действия в консоли.

### 3. Объяснение архитектуры

> Оба интерфейса используют общий слой работы с базами данных. SQL хранится
> отдельно от пользовательского интерфейса. MySQL является источником фильмов,
> а MongoDB хранит историю и статистику запросов.

### 4. Важные технические решения

- параметры поиска передаются в SQL безопасным способом;
- результаты выводятся страницами;
- MongoClient и его пул используются повторно;
- подключение открывается и закрывается вместе с приложением;
- ошибки внешних сервисов преобразуются в понятные сообщения;
- веб-маршруты проверяются автоматическими тестами.

### 5. Завершение

> Проект демонстрирует модульную архитектуру Python-приложения, совместную
> работу реляционной и документной баз данных, создание двух интерфейсов и
> практическое применение обработки ошибок, логирования, тестирования и
> управления ресурсами.
